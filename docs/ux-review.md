# 2026-10-21 销售工作区界面评审

状态：用户“推进”已采纳为D035/R112；0.10/code9界面实现及自动化子范围完成并安装。原拨号规则与默认5秒保持。本人两轮独立操作/60秒准备目标仍待测。

## 当前问题

- 同一长页面混合导入、资格维护、分页、计划、运行控制、结果、统计和历史，名单越长，运行入口离选择区域越远。
- “安排选中联系人”“确认本批并启动”“启动已确认的手机队列”“立即处理下一条”等并列且同色，操作顺序依赖用户记忆。其中后两者仍有不同模式/前置条件，不应机械删除业务能力，也不宜全部展示在LIVE主流程。
- 截图已选0条且旧队列FINISHED，仍展示下一阶段按钮；需要按状态解释“尚未开始新一批”，并阻止无效操作。服务端RUNNING仅表示队列元数据，不能单独展示为手机已启动；必须结合原生票据与批次就绪情况。
- 每条“资格已声明”联系人仍有“记录已有资格/撤回资格/拒绝联系”三个按钮，重复维护操作挤占选择空间。拒绝联系仍必须容易找到，未知资格不得默认当作合格。
- IP/版本32/FINISHED/API接受/NO_ANSWER/COMPLETED等面向诊断的信息占据日常操作区域。应隐藏原始字段、展示中文状态，并保持“系统提交不等于接通”的证据区分。
- 长期悬浮的多行警告会遮挡任务区域。应在缺失项旁解释具体原因，运行时以简短状态和下一动作反馈为主。
- 空时间默认5秒后不易理解，也给设置和确认留下很短时间。若改变默认执行时机，须作为行为建议另行明确，不能在界面改造中默默改变。

## 建议的最小改造范围

1. 三个工作区域：名单（导入/选择）、拨号（当前批次/下一动作/结果）、记录（历史及详情）；连接、选卡和账号放设置入口。导入表单按需打开，不常驻占满首屏。
2. 一条引导流程：选择名单→设置开始时间→核对本批→原生确认后启动。可以把创建计划和启动包装成一个引导入口，但仍保留创建计划、刷新校验、明确原生确认、启动的独立检查；失败中止，禁止隐式授权或自动重试。实施时补相应失败/取消/重复点击回归。
3. 当前屏幕只有一个主动作；暂停始终容易找到。等待时显示预计下一通时间；有待核对时优先展示当前通话结果；未知或停止后显示具体阻断原因及明确重新安排入口，不显示会暗示自动恢复的按钮。
4. 简化名单行和运行页，只显示号码掩码、资格、选中状态及必要动作；历史默认收起。修改资格等低频操作进入详情，拒绝联系仍在日常流程可快速触达。

上述为建议，不新增CRM、报表、云端部署或平台范围。不得为了减少按钮而删除资格检查、SIM确认、暂停、拒绝联系或未知结果保护。

## 本轮优化的建议结束标准

以下是项目验收目标，尚未实测，不是外部规范给出的数字：

- 对已导入合格名单，销售无需开发者指引，在60秒内完成一次批次准备与最终确认；时间只计准备，不计等待及真实通话。
- 在S23上，用户本人连续两轮独立完成选择→安排/核对→确认→填写结果→结束，无需助手找按钮、滚动定位或解释启动键。
- 拨号工作屏无需滚过整份名单或历史即可看到当前状态、数量、下一步和暂停；每个状态只有一个主动作。
- 覆盖零选中、资格未明/拒绝、过去时间、非工作时段、忙线、断网、UNKNOWN、暂停/冷开；各自有可见、具体且可执行的说明，不产生额外授权或自动重拨。
- 200条生成名单和既有历史不会把运行控制推出可达范围；不因此新增200次生产硬上限，不用仿真通过证明全天真实通话可靠。
- 误拨、选错SIM、无确认授权、重复授权、未知自动重放等严重问题为零；现有核心回归保持通过。
- 达到上述条件且没有阻断任务的问题后，本轮收口。颜色、图标及动画等改动仅在有明确任务障碍时再做。

真实无线通话T845仍是独立的未运行验收项，界面优化通过不能替代。真实通话需当轮授权；本评审没有拨号动作。
