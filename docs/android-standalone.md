# 安卓独立任务仿真

模块：prototypes/android/standalone；应用“销售任务仿真”，包名com.mantou.salesdialer.standalone。与“销售拨号探索”分开安装，无电话/网络权限，不使用真实号码。现支持人工与单次原生定时仿真，真实拨号尚未接入。

在项目根执行（使用已有项目工具）：
```powershell
pwsh -NoProfile -File tools/check-standalone.ps1 -Mode Test
pwsh -NoProfile -File tools/check-standalone.ps1 -Mode Build
```
APK：prototypes/android/standalone/build/outputs/apk/debug/standalone-debug.apk。

手机操作：创建3条演示任务→重新安排剩余任务→模拟下一条→模拟结果未接/已接通/核对未知→下一条。提交只在北京时间工作日09:00–18:00执行。暂停使旧计划失效，需再次明确重排。退出应用不清空状态；强制停止后重新打开，仍需核对待处理任务。数据损坏时保留现场，不自动重置。测试结束点“暂停并作废旧计划”，或关闭应用；暂停会取消单次闹钟；无真实拨号服务。

创建200条仅在空演示库时使用；不覆盖已有演示历史。200是测试样本，不是生产总尝试上限。当前同一演示目标只执行一次，无自动重拨。

真机界面回归（已连接/解锁、应用库为空）：
```powershell
node tools/check-standalone-device.mjs --run
```
读取既有本地设备绑定，安装独立APK，执行3条合成任务、一次force-stop/重开、拒绝联系和暂停。不能直接在已有演示数据上重跑；脚本会拒绝空库断言，不清除用户数据。原受控拨号APK/许可不由本脚本修改。真实手机链路与独立自动队列仍待实现/验收。

## R084单次定时操作
新增“追加3条演示任务”和“30秒后模拟下一条”。后者显式重排并为首个可用演示目标注册系统精确闹钟（须先点“允许精确定时”并在系统设置授权），按Home可让应用退到后台，回来查看“定时”结果。到点后超过30秒就跳过，不自动补发。回调成功只产生模拟尝试，仍需点模拟结果核对。
手机重启或应用强制停止后重新打开，旧定时不重新注册；界面冷启动会暂停残留计划，需要明确重新安排。正常后台Receiver唤醒进程按原窗口守卫处理。需要闹钟和提醒权限，不需要电话或网络权限。
新增真机入口：`node tools/check-standalone-timer-device.mjs --run`，要求已解锁、现有演示库暂停且无待核对；安装升级保留旧数据，仅追加3条合成任务。记录后台回调是实际模拟提交还是超时跳过，再验证force-stop重开不补发。不会清空原数据。

R084补充：单次定时仿真需允许“闹钟和提醒”，应用电池设置允许后台运行。安排前会检查这两项；当前仅合成任务，无电话或网络权限。后台调度失败时保留证据，超过30秒执行窗口跳过。请勿清除演示库来重跑测试。

## R085主动再次尝试
选择“选择目标再次尝试”→选择已核对且结果明确的DEMO目标→“重新安排剩余任务”→“模拟下一条”（或定时下一条）。准备后自动暂停，原计划/闹钟失效；该目标仍按任务顺序执行，不隐含立即插队。拒绝联系、存在待核对任务或所选结果为UNKNOWN时停止。可用“查看尝试历史”看每个A序号、模拟回执和核对结果。准备不会增加尝试数，新提交才增加。
旧演示库自动读取并在下次写入迁移，不清空。当前演示资源最多1000次尝试/64KiB，不是生产限额。真机回归：node tools/check-standalone-retry-device.mjs --run；只操作合成任务，前置条件见implementation-plan。退出前点暂停。
